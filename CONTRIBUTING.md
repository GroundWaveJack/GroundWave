# Contributing

Groundwave welcomes pseudonymous contributors. Do not include legal names, private contact data, credentials, precise private deployments, or unnecessary radio identifiers. Contributions are reviewed on technical merit and conduct.

Start with documentation corrections, test fixtures, measured hardware evidence, profile analysis, accessibility, threat-model cases, or upstream-compatible patches. Open an issue or RFC before substantial new architecture, protocols, repositories, or hardware requirements.

Pull requests must state maturity, what exists versus what is proposed, security/privacy effects, tests, external standards affected, and any AI assistance that requires human verification. By contributing, you assert authority to submit the work under the repository's applicable terms; licensing gaps are tracked in [LICENSES.md](LICENSES.md).

Use ADRs for accepted architecture decisions and RFCs for proposals. Keep commits coherent, do not push to `main`, and run documentation checks. Hardware evidence includes configuration, instrumentation, environment, procedure, raw results, uncertainty, and failures.

See the [code of conduct](CODE_OF_CONDUCT.md), [governance](GOVERNANCE.md), and [security process](SECURITY.md).
