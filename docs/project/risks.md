# Project risks

**State:** Architecture-under-design risk register.

Primary risks are architecture outrunning implementation, misuse or trivialization of the Harriet tribute, identifier collision or public confusion, false or replayed distress, stale cancellation, rescue relays implying reachability they do not have, markers becoming covert permanent trackers, location uncertainty being hidden, metadata becoming surveillance, translation expanding trust, scarce-resource abuse, incompatible profiles, unmaintained dependencies, regulatory mistakes, unsafe hardware, ambiguous licensing, founder concentration, and documentation fragmentation.

Mitigations include visible attribution, cultural-stewardship review, staged identifier migration, maturity labels, authenticated activation and cancellation, temporary marker identifiers, explicit location method and uncertainty, bounded emergency queues and cycles, partition evidence, minimization, explicit receipts, quotas, fixtures, upstream collaboration, regional profiles, measured qualification, license review, public decisions, and a single canonical documentation repository. Residual risk remains and is reviewed in RFCs and releases.
