# Project risks

Primary risks are architecture outrunning implementation, metadata becoming surveillance, translation expanding trust, scarce-resource abuse, incompatible profiles, unmaintained dependencies, regulatory mistakes, unsafe hardware, ambiguous licensing, founder concentration, and documentation fragmentation.

Mitigations include maturity labels, minimization, explicit receipts, quotas, fixtures, upstream collaboration, regional profiles, measured qualification, license review, public decisions, and a single canonical documentation repository. Residual risk remains and is reviewed in RFCs and releases.
