# ADR 0010: Adopt Harriet as the public project name

**Status:** adopted

**Date:** 2026-07-14

**Supersedes / superseded by:** Supersedes [ADR 0009](0009-groundwave-name-is-provisional.md)

**Decision owner:** Jack

**Related RFC:** [RFC 0001](../rfc/0001-adopt-harriet-name.md)

## Context

Groundwave was retained as a provisional working name by ADR 0009. RFC 0001 records the maintainer's decision, cultural obligations, collision limits, staged migration, and rollback conditions.

## Decision

Adopt **Harriet** as the public project and platform name, in honor of Harriet Tubman. Groundwave becomes the historical name and remains embedded in legacy repository identifiers during staged migration.

This does not rename or select a GitHub account, repository, local directory, branch, remote, domain, executable, package, crate, module, protocol identifier, or external resource.

## Consequences and limitations

Current normative documentation uses Harriet. Historical sources, audit evidence, and literal legacy identifiers retain Groundwave or `GroundWave` as accuracy requires.

RFC 0001 defines permanent obligations for historical accuracy, ordinary-person accessibility, and prevention of trivialization, gamification, mascot use, and implied endorsement. The collision review is not trademark clearance or exclusivity. Technical identifiers remain unresolved.

## Security and privacy

No trust boundary, security property, privacy claim, or implementation changes. Future ordinary-user experience must expose simple privacy, urgency, degradation, and acknowledgment choices without requiring command-line or networking expertise. That is not a current-interface claim.

## Conformance evidence

Evidence is a consistent documentation migration, current entry points, classified legacy-name occurrences, unchanged archives, and passing documentation, identity, and scope checks. A conflicting current normative name, changed archive, or settled-identifier claim falsifies conformance.

Adoption records naming only. It does not assert implementation, testing, qualification, or release.

## Follow-up and review trigger

Separate decisions must resolve any organization, repository, domain, executable, package, crate, module, protocol, redirect, or compatibility migration. Reconsider through a public RFC and ADR if credible evidence shows cultural harm or misuse, material collision or legal risk, accessibility or exclusion concerns, or incompatible migration constraints.
