# Documentation style

Lead with purpose and maturity. Use plain language, define acronyms, link primary standards, and state ownership boundaries, present evidence, limitations, security/privacy impact, conformance, and open questions. Use source-controlled Mermaid only when it clarifies relationships.

Prefer “resilient,” “bounded best effort,” “user-controlled,” and “infrastructure-independent where possible.” Avoid militarized framing, literal “unstoppable” claims, unsupported censorship or security promises, and future tense that sounds committed. Capitalize Groundwave only as the project name.
