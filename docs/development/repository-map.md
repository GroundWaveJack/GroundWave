# Repository map

**State:** Adopted project structure as of 2026-07-14.

The `HarrietProject/Harriet` repository is canonical for project direction, architecture, governance, security, standards posture, and cross-repository development rules. `harriet-fieldnode` contains an experimental relay reference. `harriet-app` is reserved pending an edge-client RFC. Other placeholders should receive no implementation until consolidation or archival is decided publicly.

Create a repository only for independent source, release cadence, security boundary, or maintainer ownership—not as a roadmap signal. Full evidence is in the [repository audit](../project/repository-audit.md).

Project-wide doctrine, vocabulary, threat model, integration posture, and conformance contracts stay here. Embodiment-specific source, bills of materials, procurement records, firmware, build evidence, and release artifacts belong with the implementing subproject and link back to their governing profile. Duplicated policy is replaced with a link and a named version, not copied prose.
