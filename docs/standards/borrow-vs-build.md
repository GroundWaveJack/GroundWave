# Borrow versus build

**State:** adopted doctrine

Harriet owns the missing connective layer: human-intent semantics, communication-envelope policy, provenance, declared translation loss, and mappings between supported profiles. It should profile or integrate solved layers instead of absorbing them.

Build only when a required semantic cannot be expressed through an appropriate standard, upstream extension, or thin profile. An RFC must describe the gap, evaluated alternatives, layer ownership, security cost, interoperability path, external verification still required, upstream discussion, maintenance capacity, migration, and removal criteria. A prototype is not evidence that a new protocol is necessary.

Harriet should not build new cryptography, generic routing, codecs, databases, radio firmware, operating systems, or package managers merely to appear complete.
